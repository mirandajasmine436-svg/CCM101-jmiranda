# 💭 Mission Reflection — Laboratory 05

📦 Object storage is far better suited for storing millions of photos than a traditional block storage hard drive because of how it handles scale and access. 🧱 Block storage splits data into fixed-size chunks that live on a single attached disk, which means its capacity is limited by the size of that disk and it must be managed by an operating system file system. 🌐 Object storage, on the other hand, stores each photo as a self-contained object with its own metadata and unique identifier in a flat namespace, so there are no folder limits or disk boundaries to worry about. 🔗 Each photo becomes directly accessible over HTTP through an S3-compatible API, which is exactly what a photo-sharing app needs when serving images to users around the world. 📈 This combination of unlimited horizontal scaling, rich metadata, and web-native access is why object storage is the industry standard for unstructured media.

🐳 Using Docker made deploying the MinIO storage server dramatically easier than a manual installation would have been. 🚀 With a single `docker run` command, Docker pulled the MinIO image, configured the server, exposed the API and console ports, and started the service — all in one step. 🔑 The `-e` flags let me inject the admin credentials as environment variables without editing any config files, and the `-p` flags mapped the container's ports directly to my KillerCoda environment. 🔄 If anything had gone wrong, I could simply run `docker rm -f minio-server` and start over in seconds, which made experimentation feel safe and fast.

🪣 A "bucket" in cloud storage is the top-level container that holds objects, similar to a folder but with important differences. 🏷️ Buckets have globally unique names, they exist in a flat namespace rather than a true hierarchy, and every object inside them is identified by a key. 🔐 All objects in a bucket share the same configuration — permissions, versioning rules, and lifecycle policies — which makes them the natural unit for organizing data by application, project, or client. 📸 In this lab, the `client-photos` bucket was where user-uploaded images would live for the photo-sharing application.

🛡️ Large enterprise companies protect object storage data from physical server failures through multiple layers of redundancy. 🌍 They replicate data across several servers, racks, or even geographic regions so a single crash cannot destroy the only copy. 🧩 They also use erasure coding, which splits data into fragments with parity information so any missing pieces can be mathematically reconstructed. 🕰️ On top of that, versioning preserves older copies of objects, and lifecycle policies move data to cheaper long-term storage tiers automatically. ☁️ Services like AWS S3, for example, store data across at least three availability zones by default, which is why they can promise eleven nines of durability.
